# NiPoPoW Proof Verifier — Design Spec

**Status:** Draft
**Date:** 2026-05-12
**Package:** `@mwaddip/ergots-proof` (v1 of the `ergots` monorepo)
**Interface contract:** `facts/proof.md` (load-bearing for other packages — that file wins on any interface disagreement)

## Goal

A pure-TypeScript library that parses, serializes, and verifies Ergo
NiPoPoW proofs. Browser-compatible (no Node.js APIs). Validated
byte-for-byte against the `ergo-nipopow` Rust crate that the JVM-compatible
Ergo node implementations use.

The verifier is stateless: bytes in, structured result out. It does not
fetch proofs, persist headers, or follow the chain tip. Those concerns
live in future packages.

## Non-goals (v1)

- **Proof construction.** Verifier only. Proof-building requires a local
  header chain with cached interlinks — that's a different package.
- **Transport.** Callers fetch proofs over their own channel (HTTPS to a
  REST node, WebSocket to a gossip peer, a captured file, …) and hand
  the verifier a `Uint8Array`.
- **Storage.** No header chain, no IndexedDB, no on-disk anything.
- **Light-client sync.** Bootstrapping a header chain from a verified
  proof and following the tip lives in a separate package (`light-client`)
  that depends on this one.
- **Multi-peer best-arg selection (KMZ17 §4.3 multi-peer voting).** The
  pairwise `compareProofs` is in scope; the orchestration around
  collecting and voting on multiple proofs is not.
- **Continuous-mode proofs.** ergo-node-rust sets `continuous = false`
  unconditionally (`chain/src/nipopow_proof.rs:43-44`). v1 matches that.

### Public surface

Primary export (`@mwaddip/ergots-proof`):

```ts
parseProof(bytes: Uint8Array): NipopowProof
serializeProof(proof: NipopowProof): Uint8Array
verifyProof(bytes: Uint8Array, opts?: { checkPoW?: boolean }): VerificationResult
compareProofs(a: Uint8Array, b: Uint8Array): boolean

type VerificationResult = {
  suffixTipHeight: number
  totalHeaders: number
  continuous: false         // see non-goals
  headers: Header[]         // strictly-increasing height order
}
```

The shape of `VerificationResult` matches `NipopowVerificationResult` in
`chain/src/nipopow_proof.rs:35-56` so the fixture comparison is direct.

Subpath export (`@mwaddip/ergots-proof/envelope`):

```ts
parseGetNipopowProof(body: Uint8Array): GetNipopowProofRequest
serializeGetNipopowProof(req: GetNipopowProofRequest): Uint8Array
parseNipopowProofEnvelope(body: Uint8Array): Uint8Array  // returns inner proof bytes
serializeNipopowProofEnvelope(innerProof: Uint8Array): Uint8Array

const GET_NIPOPOW_PROOF = 90
const NIPOPOW_PROOF = 91
const GET_NIPOPOW_PROOF_MAX_SIZE = 1000
const NIPOPOW_PROOF_MAX_SIZE = 2_000_000
```

Subpath isolation lets the future gossip package depend on the envelope
codec without forcing the verifier onto its consumers.

### Type model

Mirrors the Rust types in `ergo-nipopow` and `ergo-chain-types` closely
enough that fixtures can be JSON-compared field-by-field, but uses idiomatic
TS:

- `Uint8Array` for all byte blobs (block ids, digests, raw proofs)
- `bigint` for any value that can exceed `Number.MAX_SAFE_INTEGER`
  (`n_bits` target unpacking, difficulty arithmetic in `compareProofs`)
- `number` for everything safe (`height`, `timestamp` fits comfortably)

The wire format is fixed — these types are shaped to round-trip through
the Scorex serializer and produce byte-identical output to the Rust crate.

## PoW verification — Autolykos v2

Per the brainstorm: verifier-side Autolykos v2 is light. Mining searches
for a nonce against a 2^26-element table; verifying just recomputes
`genIndexes(seed)` once for the given nonce, hashes the indexed elements
with blake2b-256, and checks the resulting sum is below the difficulty
target.

Roughly 32 blake2b-256 invocations per header. Browser-cheap.

Default `checkPoW: true`. Opt-out (`{ checkPoW: false }`) only for tests
on synthetic chains where headers don't have real Autolykos solutions —
mirrors `verify_nipopow_proof_bytes_no_pow` in
`chain/src/nipopow_proof.rs:257`.

Without PoW, the verifier reduces to structural validation, which means
"trust whoever produced these bytes." Keeping PoW on by default preserves
the value proposition.

## Validation strategy

Three layers, all driven from `fixture-gen/` — a Rust crate that depends
on the same `ergo-nipopow` crate ergo-node-rust uses, dumps fixtures into
`packages/proof/test/fixtures/`, and is regenerated by `cargo run -p
fixture-gen` from the same git rev.

### Layer 1: synthetic-chain fixtures

Port the test setup from `chain/src/nipopow_proof.rs:360-437`
(`build_chain_with_interlinks`). For each chain length × `m` × `k` ×
anchor combination, dump:

- The serialized proof bytes
- Every intermediate parsed field as JSON (each `PoPowHeader`, the
  interlinks vec, the merkle proof, the verification result struct)

TS asserts: parse the bytes, every parsed field matches the JSON, the
verification result matches the Rust struct.

Variations:
- Chain lengths: 10, 20, 64
- `(m, k)` pairs: (2, 2), (6, 10) [JVM default], (8, 24) [larger]
- Anchor: `None` (use tip) and `Some(tip_id)` (explicit suffix tip)
- Genesis loader variations: present and absent
  (mirrors `build_proof_skips_loader_for_genesis` in the Rust)

### Layer 2: real-world fixtures

- A testnet proof: drive a live `ergo-node-rust` testnet node to build a
  proof at a pinned height, capture the bytes.
- A mainnet proof: same, against mainnet.
- A JVM-generated `GetNipopowProof(m=6, k=10)` request: capture once from
  a JVM node's outbound message (per `facts/nipopow.md` line 232 — pin
  from `ErgoNodeViewSynchronizer.scala:1032`).

These hit the real wire format, real PoW, and real difficulty targets.
Without them, the synthetic fixtures could agree with each other while
both diverging from production.

### Layer 3: mutation tests

Single-byte flips at varied offsets across each layer-1 and layer-2
fixture. Every mutation must cause `verifyProof` to fail. Mirrors
`verify_mutated_proof_fails` in `chain/src/nipopow_proof.rs:540`.

## Browser compatibility

Hard rules enforced by lint + test runner config:

- No `Buffer`. Use `Uint8Array` everywhere.
- No `process`, `fs`, or other Node built-ins outside test files.
- No `node:crypto`. Crypto is `@noble/hashes` only.
- ESM only, ES2022 target.
- Bundle as ESM with type declarations; no CJS.
- Vitest runs each test file under both `node` and `jsdom` environments
  to catch accidental Node-isms.

## Dependencies

Runtime:
- `@noble/hashes` 2.x — blake2b-256 (and blake2b-512 if any code path needs it; currently no)

No `@noble/curves` in v1. The verifier doesn't validate signatures, and
the miner public key inside `AutolykosSolution` is consumed as raw
serialized bytes (33-byte compressed secp256k1 point) feeding the
Autolykos v2 hash input — no curve arithmetic required on the verify
path. If implementation reveals a path that needs scalar/point ops, we
revisit.

Dev:
- `typescript` ^5.5
- `vitest` ^2
- `tsup` ^8
- `@types/node` ^22 (test-only)

## Test plan

- **Unit per module**: hand-crafted vectors for VLQ encode/decode,
  blake2b-256 known answers, merkle proof verification on tiny trees,
  header id derivation against pinned bytes.
- **Round-trip**: every layer-1 and layer-2 fixture — `parse → serialize`
  must produce byte-identical output. Captures any serialization drift.
- **Verify**: every fixture passes `verifyProof`. The returned
  `VerificationResult` matches the Rust fixture JSON field-for-field.
- **Mutation**: every mutated fixture fails `verifyProof`.
- **Compare**: cross-fixture `compareProofs` calls — results match the
  Rust `is_better_than` output.
- **PoW toggle**: synthetic fixtures with `checkPoW: false` pass, with
  `checkPoW: true` either pass (if synthesized with real PoW) or fail
  (if not). Real-world fixtures must pass with `checkPoW: true`.

## Risks and mitigations

| Risk | Mitigation |
|------|------------|
| Autolykos v2 implementation drift from JVM canonical | Layer-2 mainnet fixture is the source of truth; mainnet PoW must verify in CI. |
| Scorex serialization edge cases (zero-length vectors, optional fields) | Layer-1 fixtures cover varied chain lengths and anchor presence; round-trip test catches asymmetry. |
| Browser/Node divergence (e.g. `globalThis.crypto`) | Dual-environment vitest runs. |
| Difficulty target arithmetic (`bigint` precision, sign) | Mainnet header `n_bits` unpacking has explicit tests; `compareProofs` exercises difficulty math on real proofs. |
| `@noble/hashes` 2.x API drift | Pin to a specific minor version; integration tested in `frots` already. |

## Open questions (not blockers)

- Should `verifyProof` return a `Result`-style discriminated union
  (`{ ok: true, value } | { ok: false, error }`) or throw on failure?
  Throwing is more idiomatic JS but loses the typed error variants the
  Rust `ChainError::Nipopow(...)` carries. Decision deferred to
  implementation plan.
- Whether to expose a streaming parser for very large fixtures or stick
  with eager `Uint8Array → struct`. Eager is simpler and the 2 MB cap
  makes streaming unnecessary; revisit only if memory becomes a real
  browser concern.
