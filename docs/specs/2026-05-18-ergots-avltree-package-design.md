# `@ergots/avltree` — Package Design Spec

**Status:** Draft
**Date:** 2026-05-18
**Package:** `@ergots/avltree` (new — phase 2h-a in the `ergots` monorepo)
**Interface contract:** `facts/avltree.md` (written alongside this spec; that file wins on any interface disagreement)
**Brainstorm transcript:** this session, 2026-05-18

## Goal

A pure-TypeScript, browser-runnable, byte-faithful port of the verifier slice of Ergo's AVL+ batch authenticated tree algorithm (KMZ16 / [2016/994](https://eprint.iacr.org/2016/994)). Given `(startingDigest, proof, treeConfig, operations[])`, the package decides whether the proof is well-formed for the digest and computes per-operation results plus the resulting new digest.

The package mirrors the role and surface of the standalone Rust crate `ergo_avltree_rust` (the fork at `~/projects/ergo_avltree_rust/` HEAD `879545c`, which includes the 3 upstream PRs #10/#11/#13 applied). Sigma-rust's `ergotree-interpreter` consumes that crate via direct dependency; in the TS port, `@ergots/ergoscript` consumes `@ergots/avltree` the same way. The package is independently useful for any consumer wanting AVL+ proof verification without parsing/evaluating a full ErgoTree — wallets, DEX simulators, light clients verifying state transitions.

This is phase 2h-a of the broader phase 2h work. Phase 2h-b is the separate spec for wiring `@ergots/ergoscript`'s 11 SAvlTree.* method handlers (plus `LastBlockUtxoRootHash` if confirmed in 2h-b scoping) to call into this package.

## Non-goals

- **`BatchAVLProver` (prover side of `ergo_avltree_rust`).** Verifier-only port. The project identity is a verifier kernel (light clients verify; they don't construct AVL+ trees). The Rust prover IS used during fixture generation (see Validation strategy) but is not ported to TS.
- **`persistent_batch_avl_prover` and `versioned_avl_storage`.** Storage abstractions with no consumer in the verifier path.
- **Direct exposure of the internal stateful `BatchAvlVerifier` class on v0.1.0.** Day-1 public API is the functional wrappers (`verifyAvlBatch`, `verifyAvlLookup`). The class is designed with clean inspectable state (per the option-3 deferred decision in this session) so promoting it to public surface later is a one-line export change when a real debug/diagnostics consumer surfaces.
- **AVL+ method-handler eval arms.** That's 2h-b's scope (separate spec covering the 11 SAvlTree.* handlers + `LastBlockUtxoRootHash` arm in `@ergots/ergoscript`).
- **`AvlTreeData` (the wire-format MIR type).** Stays in `@ergots/ergoscript`'s `mir/types.ts`. This package defines its own verifier-input shape `AvlTreeConfig`. The 2h-b integration adapts at the call boundary.
- **Cost accounting.** This package charges no cost. Cost is an ergoscript concern, charged by the SAvlTree.* handlers in 2h-b around the call into this package.
- **Real mainnet AVL+ proof corpus.** v0.1.0 tests use synthetic proofs generated by `BatchAVLProver` at fixture-gen time. Real mainnet fixtures may surface in 2h-b's ergoscript-integration spec if chain-state infrastructure makes them cheaply sourceable.
- **Performance benchmarks.** Out of scope for v0.1.0. Measure only if a real bottleneck surfaces in 2h-b or later.

### Component graph

- **Public surface (`verify.ts`)** wraps `batch-verifier.ts`. The only file consumers import from is `index.ts`, which re-exports from `verify.ts`, `operation.ts`, `types.ts`, `errors.ts`.
- **`BatchAvlVerifier` (`batch-verifier.ts`)** is the orchestrator. Owns the AVL tree state (`root: NodeId | null`, `height: number`, current digest, proof-traversal indices `directionsIndex` / `lastRightStep` / `replayIndex`), holds the proof bytes, exposes `performOneOperation`. Construction runs `proof-decode.ts` to reconstruct the tree and verifies the resulting root labels to `startingDigest`.
- **`proof-decode.ts`** parses the proof's packed post-order tree representation (`LABEL_IN_PACKAGED_PROOF` / `LEAF_IN_PACKAGED_PROOF` / internal-node-with-balance tokens), pushes nodes onto a stack, and asserts the final root label matches `startingDigest`. Pure with respect to verifier state.
- **`modify.ts` / `delete.ts`** are the per-operation algorithmic engines. They walk the tree via `tree-traversal.ts`, mutate nodes via `node.ts` constructors, apply rotations via `rotation.ts`, and use `operation.ts::updateFn` for the per-op old→new value transformation.
- **`node.ts`** is the deepest leaf of the dependency graph. Holds tree-node types and blake2b-256 labeling. Only place `@noble/hashes/blake2.js` is imported.
- **`tree-traversal.ts`** holds the three verifier-specific helpers that consume the proof's "directions" bit-string. Stateful but trivial logic; isolated so the proof-byte-level state mutations are inspectable.

### Data flow (verifyAvlBatch end-to-end)

```
1. verify.ts::verifyAvlBatch
   ├── validate inputs (config.keyLength > 0, etc.) → throws AvlVerifyError on programmer error
   ├── construct: const v = new BatchAvlVerifier(startingDigest, proof, config)
   │   └── BatchAvlVerifier constructor calls proof-decode.ts::parseProofPackedTree
   │       ├── walk proof bytes; build LeafNode / InternalNode / LabelNode by token
   │       ├── on END_OF_TREE_IN_PACKAGED_PROOF: assert stack.length === 1
   │       ├── compute root label via node.ts::label(root) → blake2b-256
   │       └── assert startingDigest.starts_with(rootLabel)
   │       (failure during reconstruct → return null)
   │
   ├── for each op in operations:
   │   └── v.performOneOperation(op)
   │       ├── save replayIndex := directionsIndex (for delete replay)
   │       ├── route by op.tag:
   │       │   ├── Lookup / Insert / Update / InsertOrUpdate / UpdateLongBy / UnknownModification
   │       │   │   → modify.ts::modifyHelper
   │       │   └── Remove / RemoveIfExists → delete.ts::deleteHelper
   │       ├── update v.root, v.height
   │       └── on verification failure: v.root = null (poisoning), return null
   │
   └── on success: return { newDigest, results }
```

**Key invariants enforced through this flow.**

1. `directionsIndex` only advances; never rewinds (replay uses separate `replayIndex` initialised per-operation).
2. After any operation fails, `v.root = null` so all subsequent operations also fail (sigma-rust's "tree poisoned after failure" rule per `batch_avl_verifier.rs:166-170`).
3. The proof's "directions" bits must be consumed exactly as the verifier descends; off-by-one in proof traversal is a primary failure mode the byte-equality test catches.
4. All tree mutations produce new nodes (no in-place modification of nodes pushed during proof decoding) so the original reconstructed tree remains inspectable for debugging if the option-3 internal class is ever promoted to public.

## Public API surface (v0.1.0)

```ts
// Functional wrappers — the consumer-facing surface.
export function verifyAvlBatch(
  startingDigest: Uint8Array,         // 33 bytes (32-byte root + 1-byte height)
  proof: Uint8Array,                   // serialized AD proof (packed post-order tree + directions)
  config: AvlTreeConfig,
  operations: Operation[],
): VerifyAvlBatchResult | null         // null = proof failed verification

export function verifyAvlLookup(
  startingDigest: Uint8Array,
  proof: Uint8Array,
  config: AvlTreeConfig,
  key: Uint8Array,
): { value: Uint8Array | null } | null // outer null = proof failure;
                                       // inner null = key absent; Uint8Array = found

export interface AvlTreeConfig {
  keyLength: number                    // bytes per key (mirrors Rust u32)
  valueLengthOpt: number | null        // bytes per value, or null if variable
  maxNumOperations?: number            // optional DoS guard
  maxDeletes?: number                  // defaults to maxNumOperations
}

export type Operation =
  | { tag: 'Lookup'; key: Uint8Array }
  | { tag: 'UnknownModification'; key: Uint8Array }
  | { tag: 'Insert'; key: Uint8Array; value: Uint8Array }
  | { tag: 'Update'; key: Uint8Array; value: Uint8Array }
  | { tag: 'InsertOrUpdate'; key: Uint8Array; value: Uint8Array }
  | { tag: 'UpdateLongBy'; key: Uint8Array; delta: bigint }
  | { tag: 'Remove'; key: Uint8Array }
  | { tag: 'RemoveIfExists'; key: Uint8Array }

export interface VerifyAvlBatchResult {
  newDigest: Uint8Array                // 33 bytes; same as startingDigest if no mutations
  results: (Uint8Array | null)[]       // per-operation old value (null = key was absent)
}

export class AvlVerifyError extends Error {
  code: string                         // see Error model
}
```

**Failure-vs-exception discipline.** Returns `null` on verification failure (untrusted-input rejection — matches sigma-rust's `savltree.rs` semantics where the SAvlTree handler returns `Value::Opt(None)` on failure). Throws `AvlVerifyError` only on programmer errors (invalid config, shape mismatches at the call boundary). The two paths are distinct: untrusted-input rejection is a value; programmer error is an exception.

## Error model

### Tier 1 — `AvlVerifyError` (thrown; 6 codes; all programmer errors)

All checked at the public entry point before any `BatchAvlVerifier` state is constructed:

```ts
export class AvlVerifyError extends Error {
  code:
    | 'invalid-config-key-length'         // config.keyLength <= 0
    | 'invalid-config-value-length'       // config.valueLengthOpt < 0 when set
    | 'invalid-config-max-ops'            // maxNumOperations < 0, or maxDeletes > maxNumOperations
    | 'invalid-starting-digest-length'    // startingDigest.length !== 33
    | 'operation-key-length-mismatch'     // op.key.length !== config.keyLength
    | 'operation-value-length-mismatch'   // op.value.length !== config.valueLengthOpt when fixed
}
```

These cannot happen with correct consumer usage; they guard against programming bugs that consumers fix at the call site.

### Tier 2 — `AvlVerifyFailReason` (internal taxonomy; 10 reasons)

Tracked by `BatchAvlVerifier` on a private `lastFailReason` field. NOT exposed in the public API on v0.1.0. Documented here for completeness so the failure-mode set is part of the interface contract. Promoted to a `getLastFailReason()` method when/if the internal class is exposed:

```ts
type AvlVerifyFailReason =
  | 'proof-truncated'                    // proof too short to decode (any OOB read)
  | 'proof-malformed'                    // invalid token, stack underflow, multiple roots
  | 'digest-mismatch'                    // reconstructed root.label !== startingDigest's root portion
  | 'directions-exhausted'               // verifier consumed past directionsBits.length
  | 'leaf-key-out-of-order'              // keyMatchesLeaf: key not in [leaf.key, leaf.nextLeafKey)
  | 'max-nodes-exceeded'                 // proof had more nodes than maxNumOperations bound allows
  | 'operation-precondition-failed'      // Insert/Update/etc. rejected by operation.ts::updateFn
  | 'tree-poisoned'                      // performOneOperation called after a previous failure
  | 'empty-tree'                         // performOneOperation called on tree with no root
  | 'operation-required-but-not-allowed' // reserved for ABI stability (currently unreachable)
```

### Invariants on the failure-vs-exception boundary

1. **Shape validation is sole and comprehensive at the public entry point.** `verifyAvlBatch` / `verifyAvlLookup` validate every shape invariant before constructing the verifier. After construction, the verifier assumes shapes are valid and operates on bytes; verification failures are about *content*, not *shape*.
2. **No throws from inside `BatchAvlVerifier` to the consumer.** Verification failures set `this.root = null` (sigma-rust's "tree poisoned" rule), store `this.lastFailReason`, and `performOneOperation` returns `null` on this and every subsequent call.
3. **Bounds-checking is explicit.** TS's Uint8Array returns `undefined` on out-of-bounds reads (silently NaN-poisons downstream); the proof decoder and direction traversal check `if (i >= proof.length) return failure('proof-truncated')` before every read. This is one of the primary correctness concerns for the port: Rust's `proof[i]` panics on OOB; TS silently returns undefined. Mutation testing on proof-length-truncation catches missing bounds checks.
4. **Internal panics from `@noble/hashes` bubble as plain `Error`.** Those are contract violations inside dependencies, not consumer-input issues.

## Browser-compat (project rules carried verbatim)

- No `Buffer`, no `process`, no `node:*`, no `node:crypto` outside `test/` setup.
- All `Uint8Array`.
- `@noble/hashes@2.2.0` for blake2b-256 only. No `@noble/curves` (no curve operations in AVL+ verification).
- No WASM direct or transitive. CI bundle scan rejects same patterns as proof and ergoscript packages.
- ESM only, ES2022 target, no top-level await.
- `bigint` for `UpdateLongBy.delta` (i64 equivalent).
- Vitest under both `node` and `jsdom` environments.

## Validation strategy

Three layers + cross-runtime, mirroring the proof package's TDD discipline.

### Layer 1 — Per-component fixture tests

- `proof-decode.test.ts` — pure tree reconstruction. Fixture: `(proof bytes, startingDigest, config) → reconstructed tree as JSON` or `null` for rejection. Validates only the proof decoder, not operation execution.
- `operations.test.ts` — per-Operation-variant coverage. One fixture set per variant × tree-state matrix (key present / key absent / boundary cases). Asserts the verifier returns the same `oldValue` byte-for-byte as the Rust verifier on the same input.
- `verify-batch.test.ts` — `verifyAvlBatch` wrapper. Per-fixture batch verification with byte-equality on `newDigest` + per-op `results[]`.
- `verify-lookup.test.ts` — `verifyAvlLookup` wrapper. Single-key reads with triple-state semantics.

### Layer 2 — Bulk corpus

`corpus.test.ts` runs the full synthetic fixture corpus. Each fixture is `(startingDigest, proof, config, operations[]) → (expected newDigest, expected results[]) | null` produced by fixture-gen. Asserts byte-equality between TS verifier output and Rust verifier output on every fixture. Load-bearing test — every check the verifier could need to perform appears somewhere in this corpus.

### Layer 3 — Mutation testing

`mutation.test.ts` — single-byte flips at varied offsets across proof bytes. Each mutation either:
- Causes a `null` return (verification failure — expected for most mutations), OR
- Returns byte-identical result (flip in tolerated padding region — should be rare and explicitly enumerated).

Target: **≥90% kill rate per Operation variant per fixture**. Mirrors Layer C3.a pattern from 2f Coll HOFs.

### Cross-runtime

Vitest configured for both `node` and `jsdom`. Every test runs in both. Same posture as proof and ergoscript packages.

New file `fixture-gen/src/cmds/avltree.rs`. Cargo.toml addition:

This unlocks the fork's verifier semantics AND the prover-side `BatchAVLProver` (used by fixture-gen for synthetic proof generation; the verifier-side TS port doesn't link to it).

**Fixture corpus structure (target ~150–200 fixtures):**

- **Per-Operation-variant fixtures.** 8 variants × varied pre-state (empty / single-leaf / balanced-10 / balanced-100 / balanced-1000 / all-left-spine / all-right-spine) → ~64 minimum.
- **Multi-op batches.** Batch sizes (0, 1, 2, 16, 256 ops) × mixed-operation-type batches → ~30 fixtures.
- **Edge cases.** Insert-on-existing-key (must fail), Update-on-absent-key (must fail), UpdateLongBy boundary cases at i64 extremes, Remove-on-absent-key (must fail), RemoveIfExists-on-absent-key (must succeed no-op), all-deletes-from-balanced-tree → ~20 fixtures.
- **Config variance.** Fixed valueLengthOpt vs variable; keyLength ∈ {1, 8, 32}; maxNumOperations + maxDeletes bounds → ~15 fixtures.
- **Adverse cases.** Truncated proofs, swapped digest, mismatched config → ~20 fixtures asserting `verifyAvlBatch` returns `null`.

Plus: port `ergo_avltree_rust`'s own test cases from `~/projects/ergo_avltree_rust/src/*.rs` test modules if they cover non-redundant scenarios.

### Confidence escalation (OVERRIDES #2)

Several areas inherently require >95% confidence before merging:

- Proof's packed post-order tree decoder (`proof-decode.ts`) — every byte position matters; off-by-one cascades to digest-mismatch.
- `nextDirectionIsLeft` / `replayComparison` byte-level bit indexing — single bit-shift error breaks delete-path verification.
- blake2b-256 node labeling input byte ordering: internal nodes hash `(0x01, leftLabel, rightLabel, balance)`; leaves hash `(0x00, key, value, nextKey)`. Padding-byte ordering matters; any swap → digest-mismatch on every fixture in that tree shape.
- Rotation algorithms — AVL+ balance invariant is preserved only if rotations are byte-faithful.

For each, the implementer escalates per OVERRIDES rule #2 if uncertainty crosses the 95% threshold during implementation. Source-first discipline (read `~/projects/ergo_avltree_rust/src/` before writing the TS port) is non-negotiable.

## Source-mapping discipline (Approach B mitigation)

Two complementary mechanisms ensure cross-fidelity with `ergo_avltree_rust` despite the TS-idiomatic decomposition (per Approach B + dual-mitigation decision).

### Per-function source comments

Each TS function gets a one-line JSDoc naming its Rust counterpart and line range:

```ts
/** Ports modify_helper's leaf-node branch (authenticated_tree_ops.rs:280-320). */
function handleLeafNode(...) { ... }
```

The comment ships in the same commit as the function body. When debugging, grep for the Rust function name and land on the relevant TS functions immediately.

### Source-Mapping table in `facts/avltree.md`

Canonical Rust-function → TS-function(s) map. Columns: Rust function (file + line range), corresponding TS function(s) (file path), and a one-sentence note on structural difference (e.g., "decomposed into 4 pure helpers" or "1:1 port"). New rows added in the same commit as the TS function. This is the canonical map used when:

- A fixture mismatches and the implementer needs to identify which TS function corresponds to a suspect Rust function.
- The upstream `ergo_avltree_rust` evolves and the table identifies affected TS code.
- A code reviewer cross-checks fidelity.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Byte-faithfulness drift from Rust reference (consensus-critical: any drift in verifier output is potentially a hard-fork-adjacent bug downstream) | Layer 2 corpus asserts byte-equality on every fixture against Rust verifier output; Layer 3 mutation testing forces every byte position to be load-bearing |
| TS Uint8Array OOB returns `undefined` (NaN-poisons downstream) where Rust `proof[i]` panics | Explicit bounds-check before every proof byte read; mutation testing on proof-length-truncation catches missing checks |
| AVL+ balance/rotation algorithm subtleties (post-order traversal + Balance ∈ {-1, 0, 1} + double-rotation cases) | Source-first discipline; per-function source-map comments; corpus fixtures covering all-left-spine / all-right-spine / mixed-depth trees |
| blake2b-256 node labeling byte-ordering (internal: `(0x01, leftLabel, rightLabel, balance)`; leaf: `(0x00, key, value, nextKey)`) | Per-function source-map comment on `node.ts::label()`; corpus fixtures with non-trivial trees catch label-input ordering bugs (any swap → digest-mismatch on every fixture) |
| Performance on large proofs (real mainnet proofs in 2h-b may exceed expected sizes) | Out of scope for 2h-a; baseline measured after 2h-b ships; optimization only if a real bottleneck surfaces |
| Future upstream `ergo_avltree_rust` changes diverging from the fork | The `~/projects/ergo_avltree_rust/` HEAD `879545c` is pinned; Source-Mapping table makes affected TS code identifiable when the upstream eventually evolves; project memory `project_fixture_gen_cargo_gotchas` to be extended with avltree patch specifics |
| `@noble/hashes` 2.x API drift | Pinned exact 2.2.0 (no caret) same as other ergots packages; upgrade gated on full corpus re-run |
| Bundle size from full verifier port | Per-file modularity keeps unused operations tree-shakeable if a future consumer wants only lookups; subpath exports introduced only if a real consumer demands tree-shaking granularity |
