# 2j-pre fix-2 triage findings (2026-05-22)

## Symptom

Layer-3 smoke from h=1 halts at h=3850 with:
```
shim error [missing-utxo]: ingest_block(3850): tx input at height 3850
references box 5527430474b673e4aafb08e0079c639de23e6a17e87edd00f78662b43c88aeda
which is not in the UTXO index
```

## Root cause — established

The missing box is **Ergo's THIRD genesis-state box (`founders`)**, per `ergo-node-rust/src/main.rs:3095` `mainnet_genesis_boxes_produce_correct_digest` test:

```rust
let expected_ids = [
    "b69575e11c5c43400bfead5976ee0d6245a1168396b2e2a4f384691f275d501c",  // emission
    "b8ce8cfe331e5eadfb0783bdc375c94413433f65e1e45857d71550d42e4d83bd",  // no_premine
    "5527430474b673e4aafb08e0079c639de23e6a17e87edd00f78662b43c88aeda",  // founders ← MATCH
];
```

Ergo's chain initializes UTXO state with **3 boxes** that exist outside any block transaction:
1. `emission_box` — large supply held by the emission contract
2. `no_premine_box` — 1 ERG, holds proof-of-no-premine in R4-R8
3. `founders_box` — foundation multisig

Constructor: `ergo_lib::chain::genesis::genesis_boxes(settings, founders_pks, threshold, no_premine_proofs)` at `external/sigma-rust/ergo-lib/src/chain/genesis.rs:95-154`. Each genesis box has `TxId::zero()`, `creation_height=0`, `index=0`.

ergo-node-rust seeds these at startup: `src/main.rs:1850-1854`.

The shim's UTXO sidecar at `tools/mainnet-validate/shim/src/utxo_index.rs` initializes empty and only inserts boxes that appear in block transaction outputs. **The 3 genesis-state boxes are never inserted**, so any block-tx input referencing them fails the index lookup.

## Why the smoke walked h=1..3849 cleanly before halting

- h=1's emission spend: walker's `GENESIS_HEIGHT` special-case (`block_walker.rs:519-524`) skips index lookup for inputs at h=1, so the missing genesis emission box doesn't surface.
- h=2..3849: every emission spend references the PREVIOUS block's output (which IS in the index from the prior block's INSERT). Emission chain is self-contained after h=1.
- h=3850: tx#2 is the FIRST block to spend the genesis FOUNDERS box. Its input lookup misses (no GENESIS_HEIGHT skip applies; the box was never inserted).

## Evidence

Trace of all activity for the target box id across h=1..3852:

```
# walk-trace findings:
REMOVE  h=  3850 tx#2 in#0 box_id=5527430474b673e4aafb08e0079c639de23e6a17e87edd00f78662b43c88aeda

        tx has 1 inputs, 5 outputs
          in #0: box_id=5527430474b673e4aafb08e0079c639de23e6a17e87edd00f78662b43c88aeda
          out #0: box_id=8e130114a671171e566382911404a67fc37ccbfe637212eaab90037e19c3336c (value=4330776400000000)

```

Zero INSERT occurrences anywhere in h=1..3852 — confirming the box is never produced by any block tx in the chain history we've seen. Combined with the genesis-box id match, the diagnosis is definitive.

## Diagnostic tools created

- `tools/mainnet-validate/shim/src/bin/walk-trace.rs` — scans h=start..max through the modifier store, logs every INSERT/REMOVE/LOOKUP matching a target box id, with full tx context dump. Useful for future fix-list triage of UTXO accounting issues.
- `tools/mainnet-validate/shim/src/bin/sidecar-query.rs` — opens a sidecar redb and queries whether a specific box id is present. Used to confirm the box was NOT in the sidecar after the smoke walk completed h=1..3849.
- `tools/mainnet-validate/shim/src/block_walker.rs:hex_full` — full 64-char hex rendering of digests (replaces `hex_short` in MissingUtxo / MissingDataUtxo error messages so triage steps have the exact id without re-running with extra logging).

## Fix shape (for fix-2 spec)

Seed the 3 genesis-state boxes into the sidecar UTXO index at sidecar-initialization time (when `indexed_up_to_height == 0`). Use `ergo_lib::chain::genesis::genesis_boxes(...)` with the appropriate `MonetarySettings` and network-specific config (mainnet vs testnet).

The shim already has access to ergo-lib via the existing path-dep. The network selection mechanism needs to be plumbed — currently the shim doesn't know whether it's pointing at a mainnet or testnet store. Options for fix-2 spec to choose:

- A. New CLI flag `--network mainnet|testnet` on the shim; harness passes it through.
- B. Auto-detect from chain context (e.g., the genesis block's structure).
- C. Try both and check which matches the store's actual genesis box digest.

Option A is the simplest and most explicit. The harness already takes `--network` (see `harness/src/cli.ts`); plumbing through to the shim is a small extension.

The `GENESIS_HEIGHT` special-case in `walk_transaction` (lines 519-524) becomes a design choice: with seeding, the emission box IS in the index, so h=1 inputs could resolve normally. Removing the special-case is cleaner but requires careful verification that h=1's emission spend behaves correctly under standard walker semantics. Reviewer pass should weigh in.
